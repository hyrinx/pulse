# 问题反馈与运行日志

这版补充默认运行记录，无需先设置环境变量。日志只保存在本机，不自动上传。

## 用户反馈

发生问题后，在现有「设置 → 关于与诊断 → 导出诊断」中选择空目录。索引、搜索或后台占用问题选择同时导出索引服务诊断，并允许此次管理员授权。将导出目录压缩后，连同以下信息提交：

- 问题发生的大致时间和时区。
- 触发步骤、预期结果、实际结果，是否可重复。
- Pulse 版本；涉及特定目录时说明本地磁盘、移动磁盘或网络共享即可，通常不需要提供私人路径。

导出包含 `diagnostics-manifest.json`，它列出每个文件的实际字节数、复制状态和 Windows 错误码。`complete:false` 表示有文件未能导出；不要把这类包当成完整采集。服务导出失败时，仍尝试保存用户日志。现有「打开目录」打开 Diagnostics 根目录，可以看到 Runtime 与 Crashes。

新运行日志不记录文件名、路径、搜索词、下载地址或文件内容。现有崩溃转储和旧日志仍可能含私人信息，导出时保留原有隐私确认。没有增加自动发送功能。

## 存储与开销

- 用户进程：`%LOCALAPPDATA%\Pulse\Diagnostics\Runtime`。
- 索引服务：`%PROGRAMDATA%\Pulse\Diagnostics\Runtime`。
- 文件名为组件和进程号，如 `app-1234.jsonl`、`index-service-5678.jsonl`，轮转文件后缀 `.1`。
- 每文件默认 2 MiB，每进程保留当前和上一份。启动和每分钟清理到最近 24 个历史文件；清理与新建并发时可暂时超过此数量。
- 生产线程只向最多 1,024 条的内存队列提交数字事件；后台线程写文件。满队列丢弃计数可见，不无限积压；停止时排空队列。崩溃或强制结束可能损失队列尾部，崩溃转储仍由原机制生成。
- 资源采样默认每 60 秒一次。未主动启用的详细索引内存探针仍保持关闭。

## 定位方式

每条 JSONL 带 UTC、单调时钟、进程/线程号、进程会话标识、写入序号、版本和构建标识。`operation`/`task`/`generation` 在对应组件和进程会话内关联；不能将不同进程中的同名编号直接等同。

| 事件 | 用途 |
| --- | --- |
| `process_start` / `process_stop` | 系统版本、位数、启动和正常退出；没有 stop 不单独证明崩溃 |
| `process_health` | 进程 CPU、工作集、私有内存、句柄、丢弃事件数及写入错误数 |
| `navigation_*` | 导航 generation 的排队、替代、执行和完成，取消、错误标志、条目数、耗时 |
| `file_operation_*` / `file_transfer_result` | 文件操作种类、任务、条目/字节、取消、阶段与可用的 HRESULT |
| `update_*` | 检查、下载、校验、等待操作、启动安装、保存会话及退出握手 |
| `index_hierarchy_rejected` | 异常节点编号、父节点编号、原因、节点总数和缓存版本 |
| `filename_map_*_failed` / `index_wal_*` | 缓存打开/映射失败，日志版本、基准快照不匹配或损坏记录位置 |
| `index_replay_rejected` / `index_cache_loaded` | 回放拒绝并需重建，或缓存正常加载及耗时 |
| `index_rebuild_begin/end` | 同一次重建的开始、结束、节点数、耗时、错误和取消 |
| `index_folder_totals_failed/ready` | 大小汇总失败/恢复、节点数、耗时及失败重试间隔 |
| `index_stage_totals` | 索引各阶段累计调用数、墙钟/线程 CPU 时间、变化数和错误数 |

只有 `cpu_sample_valid:true` 且 `interval_ms>0` 的资源样本才能计算区间 CPU。整机占比为 `cpu_us / (interval_ms * 1000 * logical_processors) * 100`；内存和句柄同样检查对应 `*_sample_valid`。`dropped_events` 或 `write_errors` 非零表示证据可能不完整。

父链原因：1 节点数量无效，2 父编号越界，3 自指，4 普通文件成为根，5 父节点不是目录，6 父节点已删除，7 环。负编号以 uint32 表示，`4294967295` 为 `-1`。重建原因：0 手动或其他，1 无可用缓存，2 启动过期，3 快照升级。

索引阶段编号依次为：0 等待、1 卷拓扑、2 USN、3 目录通知、4 增量落盘、5 合并、6 重建、7 恢复、8 名称池压缩。计数是累计值，用相邻样本差值定位持续占用。

升级阶段编号依次为：0 空闲、1 连接、2 下载、3 校验、4 就绪、5 等待文件操作、6 启动安装、7 安装中。应用退出后无法继续记录安装进程结果；安装器仍支持 `/LOG` 日志，成功重开可由新进程的启动版本佐证。本次未把临时目录中可能属于其他安装程序的日志自动收集进包。
